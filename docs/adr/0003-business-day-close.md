# ADR-0003: 마감 경계에서 잔액과 원장을 고정한 뒤 재시작 가능한 대사를 한다

- 상태: 승인(설계) · 2026-09-14

## 맥락

어제 원장과 지금 잔액을 비교하면 오늘 이체를 오류로 오인한다. `created_at < 자정`도 충분하지 않다. 자정 전에 시작해 나중에 커밋한 거래가 있을 수 있다. 또 DB sequence 최대값은 커밋 순서를 보장하지 않으므로 마감 경계로 사용하지 않는다.

## 결정

초기 규모에서는 짧은 쓰기 중단을 허용한다. `banking_clock` 한 행이 현재 영업일과 다음 마감 예정 시각을 가진다. 금융 실행과 계좌 개설은 이 행에 공유 잠금을 잡고 커밋까지 유지한다. 마감은 배타 잠금을 잡는다. 일반 고객 조회는 마감 중에도 가능하다.

자정(Asia/Seoul)에 `DayCloseCoordinator`가 다음을 **하나의 DB 트랜잭션**으로 수행한다.

1. banking_clock `FOR UPDATE`. 먼저 실행되던 모든 금융 공유 잠금이 풀릴 때까지 기다린다.
2. business_date D에 대한 마감이 없는지 확인한다. `(business_date)` UNIQUE로 중복 마감을 막는다.
3. 모든 고객 계좌(해지 포함)의 저장 잔액과 계좌별 누적 원장 합계를 읽고 `balance_snapshots`에 물리 저장한다. 원장은 D 이전 전체를 포함한다. 비교 기준은 계좌 개설 잔액 0원에서 누적된 금액이다.
4. 고객+내부 계정의 전체 차변/대변 합계 및 완료 거래별 원장 구조 위반 건수를 `day_closures`에 저장한다. ID 목록/상세는 결과의 진단 필드로 남기되 원문 계좌번호는 제외한다.
5. 마감 시각(actual cutoff), 계좌 수를 확정하고 해당 날짜의 READY 상태 reconciliation_runs를 함께 생성한다. banking_clock을 D+1로 전환한다. 커밋하면 신규 금융 실행과 계좌 개설이 재개된다.

공유 잠금 획득 후 DB 시각이 마감 예정 시각 이상인데 아직 D라면 신규 실행은 보류한다. 게이트 획득 전에 접수된 PENDING도 실행 시점의 영업일로 처리한다. 운영 중단으로 마감이 늦으면 스냅샷의 실제 경계를 기록하고 누락 영업일을 순서대로 닫는다. 예정 자정 이전에 실행 게이트를 통과한 거래는 자정 이후 커밋되어도 D 귀속이다. 날짜를 사후 변경하지 않는다.

마감은 공유 게이트를 잠그는 모든 금액 쓰기와 충돌한다. 계좌 개설도 참여하므로 계좌 집합이 고정된다. 계좌 상태 변경은 잔액을 바꾸지 않으며 마감 스냅샷은 상태에 무관하게 모든 계좌를 포함한다. 원장 직접 쓰기나 잔액 직접 SQL 수정은 애플리케이션의 정상 경로가 아니다.

## 대사 배치

마감 커밋 후 대사는 스냅샷만 읽는다. 각 계좌의 `difference = stored_balance - ledger_balance`를 계산해 MATCHED/MISMATCHED로 저장한다. 내부 자산 계정은 고객 잔액 대사에서 제외하되 전체 차변=대변 검사에 포함한다.

- `day_closures.business_date`와 `(business_date, account_id)` 스냅샷/결과 UNIQUE.
- 날짜별 `reconciliation_runs` 하나, 상태 READY/RUNNING/COMPLETED/FAILED, 재시도 횟수와 마지막 성공 account_id 저장.
- 배치 chunk마다 run 행을 잠그고 다음 ID 구간(기본 500계좌)을 처리한다. 결과 삽입과 체크포인트는 동일 트랜잭션으로 커밋한다. 다른 워커는 이미 진행된 체크포인트 이후를 처리한다.
- 프로세스 종료로 RUNNING이 남으면 heartbeat 60초 이상 경과 시 같은 run을 재개한다. 살아 있는 worker와 겹쳐도 run 행 잠금 및 결과 UNIQUE가 중복을 방지한다.
- 명시적 오류는 별도 트랜잭션으로 FAILED, 재실행은 같은 run ID에서 이어간다. 일시 중단 중 이미 끝난 결과를 삭제하지 않는다.
- 계좌가 0개인 날짜도 정상 마감 및 0건 완료로 기록한다.
- 배치 **COMPLETED는 비교 수행 완료**다. 불일치가 있으면 `hasMismatch=true`이며 성공 처리량에 묻히지 않도록 알린다. 자동 보정하지 않는다.
- 전체 원장 차변/대변 또는 거래 구조 검사가 실패하면 계좌 차액이 모두 0이어도 hasMismatch다.

## 대안과 한계

REPEATABLE READ의 메모리 내 스냅샷만으로 비교하면 프로세스 종료 후 동일 스냅샷을 재사용할 수 없다. 계좌별 순차 조회는 서로 다른 시점을 볼 수 있다. 이번에는 고정 스냅샷 저장 비용과 마감 중 쓰기 지연을 받아들인다.

10만 원장 대상으로 잠금 대기/스냅샷 시간/대사 시간을 분리해 측정한다. 마감이 오래 걸리면 버전별 잔액, 별도 스냅샷 구조 등을 후속 ADR로 비교한다. 이 설계로 24시간 무중단 금융 쓰기나 대규모 은행 마감을 구현했다고 주장하지 않는다.

## 검증 계획

AC-006/012: 마감 전에 게이트를 획득한 거래, 자정을 넘긴 커밋, 마감 후 접수 실행, 마감 트랜잭션 중단, 대사 chunk 중단, 동일 날짜 중복 실행을 재현한다. 의도적인 데이터 손상 주입은 격리된 테스트 DB에서만 수행한다.
