# ADR-0001: 모듈형 모놀리스로 시작한다

- 상태: 승인
- 결정일: 2026-09-14

## 맥락

BankCore Lab은 개인 포트폴리오 프로젝트다. 거래, 계좌, 원장, 배치 사이의 업무 경계를 보여주는 동시에 금융 정합성, 장애 처리 및 테스트를 완성도 있게 구현해야 한다. 초기부터 여러 서비스를 운영하면 분산 트랜잭션, 메시지 브로커, 배포 및 관측 환경에 많은 시간이 필요하다.

## 결정

하나의 Spring Boot 애플리케이션과 하나의 PostgreSQL 데이터베이스로 시작하되 `member`, `account`, `transfer`, `ledger`, `reconciliation`, `audit` 모듈의 의존 방향과 공개 인터페이스를 분리한다.

모듈 내부 구현은 다른 모듈이 직접 접근하지 않고 공개된 애플리케이션 서비스 또는 이벤트를 통해 사용한다. 초기 금융거래는 단일 데이터베이스 트랜잭션으로 처리한다.

## 선택 이유

- 개인 프로젝트에서 개발·테스트·배포 복잡도를 통제할 수 있다.
- 단일 데이터베이스 트랜잭션으로 출금과 입금의 원자성을 명확하게 증명할 수 있다.
- 업무 모듈 경계를 통해 아키텍처 설계 역량을 보여줄 수 있다.
- 이후 알림이나 감사 처리 등을 이벤트 기반으로 분리하며 확장 과정을 설명할 수 있다.

## 고려한 대안

### 전통적인 계층형 모놀리스

구현은 가장 단순하지만 기능이 증가하면 계층 사이의 결합도가 높아지고 은행 업무별 경계를 설명하기 어렵다.

### 마이크로서비스

독립 배포와 확장에는 유리하지만 계좌이체에 분산 트랜잭션, 보상 처리, 메시지 중복 소비 등의 문제가 추가된다. 현재 프로젝트 규모에서는 운영 복잡도가 학습 효과보다 크다.

### 서버리스 함수

기능별 배포와 자동 확장에 유리하지만 로컬 재현, 긴 배치 작업, 트랜잭션 경계와 관측 환경이 복잡해진다.

## 결과와 제약

- 초기에는 애플리케이션 전체를 함께 배포한다.
- 모듈 경계를 자동화 테스트로 검사할 필요가 있다.
- 특정 모듈의 독립 확장이 필요해지면 측정 결과를 근거로 분리를 검토한다.
- 마이크로서비스 경험 자체를 과장하지 않고, 단일 트랜잭션을 선택한 이유와 한계를 설명한다.
